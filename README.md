# 🚗 Vehicle Service API

A robust, production-ready **Spring Boot REST API** designed for managing a comprehensive vehicle catalog. It features full CRUD operations, a dynamic multi-parameter search engine with built-in pagination, database persistence backed by PostgreSQL, and seamless containerization via Docker and Docker Compose.

---

## 🛠️ Tech Stack & Architecture

| Layer | Technology | Purpose |
| :--- | :--- | :--- |
| **Language & Runtime** | `Java 17` / `Maven` | Core runtime and dependency management |
| **Framework** | `Spring Boot 3.1` | REST Web layer, Data JPA persistence, Bean Validation, and Security |
| **Database (Prod/Dev)**| `PostgreSQL 15` | Persistent data storage engine |
| **Database (Testing)** | `H2 Database` | Lightweight, isolated in-memory unit testing |
| **API Documentation**  | `OpenAPI 3.0` | Declarative contract specification (`openapi.yaml`) |
| **Tooling**            | `Docker`, `Docker Compose`, `Lombok` | Container packaging, orchestration, and boilerplate reduction |

---

## ✨ Features

- 🔄 **Full CRUD Lifecycle:** Comprehensive endpoints to create, read, update, and delete vehicle assets safely.
- 🔍 **Advanced Filtering Engine:** Dynamic search operations supporting filtering by manufacturer, model, class type, pricing brackets, text descriptions, or direct field-value matching.
- 📄 **Paginated Responses:** Optimized data retrieval payload structure preventing over-fetching.
- 🛡️ **Robust Validation & Safety:** Strongly enforced structural parameters featuring meaningful `400 Bad Request` and `404 Not Found` handled states.
- 🏗️ **Isolated Test Pipelines:** Automatic integrated unit test execution triggered seamlessly during the multi-stage Docker build pipeline.

## 🚀 Getting Started

### Prerequisites
- **Docker** and **Docker Compose** installed globally.
- *(Optional local development fallback)* **JDK 17+** and **Maven**.

### One-Command Quick Start
Bring up the entire microservice ecosystem using Docker Compose:

```bash
# Clone the repository
git clone https://github.com/Auprety7/vehicle-service.git
cd vehicle-service

# Build and start services container ecosystem
docker compose up --build
```

This automatically provisions and binds the following components:

| Container Service | Exposed Port | Role / Context |
| :--- | :--- | :--- |
| `postgres` | `5432` | PostgreSQL 15 engine mounting database `vehiclesdb` |
| `vehicles-service` | `8080` | Main application instance running the Spring Boot app layer |

> ⚠️ **Security Warning:** The configuration properties shipped inside `docker-compose.yaml` are strictly scoped for local sandbox development. **Never expose or reuse these credentials in shared staging or production environments.**

## ⚙️ Configuration Profile

The application injects infrastructure properties dynamically via standard environment variables managed natively through Docker Compose:

- `SPRING_DATASOURCE_URL` — JDBC connection URL targeting the PostgreSQL instance.
- `SPRING_DATASOURCE_USERNAME` — Root database runtime administrative user.
- `SPRING_DATASOURCE_PASSWORD` — Secure password credential mapping.
- `SPRING_JPA_DATABASE_PLATFORM` — Active Hibernate database dialect target.

## 🔌 API Specifications & Endpoints

The explicit contract is captured natively within the root `openapi.yaml` document. You can drop this raw string content straight into any online [Swagger Editor](https://swagger.io) environment to interactively examine or test payloads.

### Endpoint Routing Matrix

| Method | Path | Operational Profile | Success Code | Exception States |
| :--- | :--- | :--- | :--- | :--- |
| `GET` | `/vehicles` | Retrieves full list of cataloged vehicles | `200 OK` | — |
| `POST` | `/vehicles` | Registers a new vehicle entity | `201 Created` | `400 Validation Error` |
| `GET` | `/vehicles/{id}`| Retrieves details for an explicit vehicle | `200 OK` | `404 Not Found` |
| `PUT` | `/vehicles/{id}`| Modifies fields on an existing vehicle | `200 OK` | `400 Bad Request`, `404 Missing` |
| `DELETE`| `/vehicles/{id}`| Purges a target vehicle entity permanently| `204 No Content` | `404 Not Found` |
| `GET` | `/vehicles/search`| Performs a paginated filtered lookup | `200 OK` | `400 Invalid Parameters` |

## 🔍 Search Deep Dive

The route `GET /vehicles/search` handles localized querying via optional parameters passed directly inside the standard request query-string:

- `manufacturer` / `model` / `type` / `description` — Filters items via partial or absolute text pattern matching.
- `minPrice` / `maxPrice` — Filters vehicle array values between bounds.
- `field` + `value` — Utility query variant allowing arbitrary lookups against a single specific schema key.
- `page` — Indexed page counter (Begins at base `0`).
- `size` — Total subset length limit returned per layout block (Must be `≥ 1`).

*The wrapped system response provides structural page properties directly alongside the vehicle models metadata array (`content`, `totalElements`, `totalPages`, `pageNumber`).*

## 🔒 Security & Authentication

All exposed application paths require mandatory **HTTP Basic Authentication**. For demonstration setups, the engine provisions a single default test credential out-of-the-box:

- **Username:** `user`
- **Password:** `password`
- **Role:** `USER`

### Executing authenticated calls via CLI:
```bash
curl -u user:password http://localhost:8080/vehicles
```
*Requests targeting endpoint arrays missing a valid authorization token header automatically drop with an explicit `401 Unauthorized` block. Standard browser CSRF protection mechanisms are explicitly bypassed by design, as this system operates purely as a stateless API tailored for backend-to-backend integration clients.*

## 🧪 Verification & Test Suite Execution

You can run individual unit tests independently from container dependencies by triggering the local test profile pipeline:

```bash
mvn test
```
The test orchestrator automatically handles provisioning data models into an **in-memory H2 context**, eliminating the need for an active external PostgreSQL instance.
